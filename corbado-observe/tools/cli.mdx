The **Corbado Observe CLI** gives you scripted access to your Observe data from the terminal, without going through the management console. It is built for humans and for AI coding agents alike: every command explains itself through `--help`, output is JSON first and the full command schema is available for an agent to read.

## 1. What it is for

| Use case | Why the CLI |
| --- | --- |
| **Analysis with an AI agent** | Point an agent at your own Observe data so it can investigate a drop in login success rate or explain what an error cluster has in common |
| **Scripted exports** | Pull daily tables and time series into your own warehouse or notebooks |
| **Ad-hoc investigation** | Query catalogs and searches directly while debugging an incident |
| **Repeatable checks** | Wire an Observe query into CI or a scheduled job |

## 2. Install

The CLI is supported on macOS. Windows is available on request through [support](mailto:support@corbado.com).

On macOS, install it with [Homebrew](https://brew.sh) from the [Corbado tap](https://github.com/corbado/homebrew-tap):

```sh
brew install --cask corbado/tap/corbado
```

Homebrew puts `corbado` on your PATH. The CLI is a signed and notarized standalone executable, so it runs without a Node.js or Bun installation. Upgrade with `brew update` followed by `brew upgrade --cask corbado/tap/corbado`. Standalone downloads and release notes are on the [releases page](https://github.com/corbado/homebrew-tap/releases/latest).

## 3. Link a project

The CLI works per project. Add the first one with:

```sh
corbado switch --add
```

This opens the management console at [app.corbado.com](https://app.corbado.com), where you log in and pick the project to link. The CLI stores the project metadata in a config file and the API key in the operating system's secret store, never in plain text.

When you are unsure which permissions the link needs, start with read permissions. Every analysis and export works with read access, and you can raise the permissions later under **Observe → Settings → API keys**.

Switch between linked projects with `corbado switch`.

## 4. First steps

```sh
corbado --help
corbado guide
```

`corbado guide` walks through the common commands. `corbado schema` prints the machine-readable command documentation, which is what a coding agent reads to drive the CLI on its own.

## 5. Use with coding agents

The CLI is optimized for every coding agent: Claude Code, Cursor, Codex, Copilot and others. Give the agent the task in plain words, for example "find out why passkey logins dropped last Tuesday", and let it run the CLI. The [Observe agent skill](/corbado-observe/get-started/use-with-ai-agents) tells the agent how to read the data model.

## 6. Design

The CLI follows the `gh` model: typed commands for the common path, a raw API escape hatch for everything else, JSON-first output that can be filtered inline and full schema introspection.
