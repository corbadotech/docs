## 1. Introduction

**Corbado Observe** is an observability tool for authentication flows. It captures structured events from your application and maps them to a clear data model so you can understand user behavior, identify drop-offs, and improve login and sign-up conversion.

Whether you use passkeys, passwords, email OTP, social login, or a combination, **Corbado Observe** gives you a unified view of how users move through your authentication experience.

<Info>
  **Observe or Connect?** Use **Corbado Observe** to measure and debug the authentication you already have — it never touches your authentication path. Use [Corbado Connect](/corbado-connect/overview/welcome) if you still need to *add* passkeys to an existing identity provider. See [How Observe works](/corbado-observe/overview/how-it-works) for the full comparison.
</Info>

## 2. Why use Corbado Observe?

Most teams have limited visibility into what happens between "user lands on login" and "user is authenticated". **Corbado Observe** closes that gap:

- **Measure conversion end-to-end**\
  Track every step of login, sign-up, and recovery flows so you can pinpoint where users drop off.
- **See what your backend cannot**\
  A user who never gets past the passkey dialog produces no backend event at all. Observe captures the client-side reality: system dialogs, credential managers, silent cancellations and device-specific failures.
- **Compare authentication methods**\
  Understand how passkeys, passwords, email OTP, and social login perform side by side.
- **Segment by channel and context**\
  Use [applications](/corbado-observe/tracking/applications) and [tags](/corbado-observe/tracking/tags) to compare behavior across web, iOS, Android, or any custom dimension like country or experiment variant.
- **Understand user-level journeys**\
  Link events to your [users](/corbado-observe/tracking/user) so you can trace individual authentication paths, retries, and method switches.
- **Make decisions visible**\
  Track explicit [user and system choices](/corbado-observe/tracking/decisions) (for example login method selection) to see where users hesitate or change their mind.

## 3. How it works

You integrate a lightweight JavaScript SDK into your frontend. It observes the authentication journey in the browser, sends structured events to Corbado, and Corbado maps them onto a data model of flows, subflows and decisions that the [management console](https://app.corbado.com) turns into funnels, error analysis and per-user journeys.

Observe runs **client-side only**. There is no backend integration, no identity provider configuration, and Observe is never in the authentication path — it cannot grant, deny or delay a login.

[How Observe works](/corbado-observe/overview/how-it-works) covers the architecture, what Observe deliberately does not do, and how it differs from the analytics and monitoring tools you already run.

## 4. Two ways to send data

| Path | Summary |
| --- | --- |
| **[Autocapture](/corbado-observe/get-started/autocapture)** *(recommended)* | Deploy one script. Corbado maps your authentication journey from signals your frontend already emits — no event tagging, nothing for your team to maintain. |
| **[Precision tracking](/corbado-observe/get-started/precision-tracking)** | Instrument explicit events where you need guaranteed semantics — business-specific decisions, unusual flows, exact spec types. |

Most teams run Autocapture as the foundation and add precision events only where a step needs full resolution. Both feed the same data model. See [Integration paths](/corbado-observe/overview/integration-paths) to choose.
