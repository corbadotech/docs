Corbado Observe ships an **agent skill** following the open [agentskills.io](https://agentskills.io) standard. It teaches your AI coding agent how to instrument Corbado Observe in your frontend: which events to fire, where to fire them and how to verify the result.

The skill uses the `SKILL.md` format read by most AI coding tools, including **Cursor**, **Claude Code**, **Codex**, **GitHub Copilot**, **Windsurf** and **Gemini CLI**, plus around 70 more compatible agents.

## 1. Use it in a prompt

The fastest way, no install required:

```text
Integrate Corbado Observe into my frontend using https://docs.corbado.com/skill.md
```

## 2. Install it

To make the skill permanently available to your agent:

```bash
npx skills add https://docs.corbado.com
```

<Warning>
  The `https://` scheme is required. The bare domain form (`npx skills add docs.corbado.com`) is not accepted by the Skills CLI.
</Warning>

The command detects your installed agents and writes the skill into each one's namespaced skills folder, for example `.cursor/skills/` or `.claude/skills/`. It never edits or overwrites your existing `AGENTS.md` or `CLAUDE.md`.

<Info>
  Manually installed skills do not auto-update. Run `npx skills update -y` to pull the latest version.
</Info>

Once installed, ask your agent in natural language, for example "Add Corbado Observe tracking to my login and signup flows" or "Instrument my passkey login with Corbado Observe events".

## 3. What the agent does

The skill guides the agent through a safe, telemetry-only integration:

<Steps>
  <Step title="Decides the shape">
    Defaults to the [Observe data layer](/corbado-observe/get-started/data-layer) with one central mapping. It falls back to custom events only when you ask for hand-written tracker calls or when the app has no structurally sound central place, and it asks you first when in doubt, stating the trade-off.
  </Step>
  <Step title="Sets up the project">
    Walks you through installing the [Observe CLI](/corbado-observe/tools/cli) and pairing a project, creating one in the console if you have none, and takes the `Project ID` and `API Base URL` from there. Without the CLI it points you to the console pages instead.
  </Step>
  <Step title="Discovers the auth surface">
    Finds your login, sign-up, recovery and enrollment entry points and the methods each offers.
  </Step>
  <Step title="Models the journeys">
    Defines flow boundaries, assigns every screen to a decision and maps each method to a subflow, following the [modeling method](/corbado-observe/tracking/modeling). Where your app and the taxonomy do not match, it documents the lossy mapping instead of contorting the code.
  </Step>
  <Step title="Instruments">
    Adds the stub, tags your controls and inputs, adds the screen, outcome and validation emitters and the network and WebAuthn capture wiring, and writes the mapping module that holds every Observe name, flow boundary and subflow step. The mapping imports nothing from your app, so it can later ship as your package or from Corbado's CDN.
  </Step>
  <Step title="Validates">
    Records the data layer for representative journeys as replay fixtures against the mapping, asks you to walk the journeys with debug mode on, and checks the result against the backend with the CLI or the console's integration debugging page. See [Verify your integration](/corbado-observe/get-started/verify).
  </Step>
</Steps>
