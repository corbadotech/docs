## Create, Manage or Delete Passkeys via Passkey List Component

Passkey management lets users view and revoke passkeys registered to their account. The server-side list shows which credentials the relying party accepts. Provider-side copies may remain until the credential provider acts on best-effort reconciliation.

### General Passkey Management

<ToolingFrame
    imageURL="/images/authentication-flow/web-app/desktop/general-passkey-management-macos.webp"
    caption="Representative web passkey management flow shown on macOS"
    imageName="general-passkey-management-macos.webp"
/>

<Steps>
    <Step title="General Passkey Settings in Profile Section">
        - Users can see all the passkeys created for the current account here.
        - Each entry shows the authenticator or passkey-provider name resolved from the AAGUID stored during registration. If no trusted mapping exists, the entry uses a neutral name instead of guessing.
        - Users can initiate passkey registration in the current browser through its active credential provider.
        - Users can revoke an existing credential and, where supported, edit an RP-side friendly label. The cryptographic credential itself is not updated.
    </Step>
    <Step title="When no Passkey is created for the User Account">
        - When the user has no passkey created, the passkey list is shown empty.
    </Step>
    <Step title="Passkey Delete Modal">
        - Provide a clearly named revoke or remove action associated with the selected passkey.
        - This action is not reversible, so the user is again asked for
        confirmation on deletion of passkey. 
        - Revoke the credential in server state so every later assertion from it is rejected. Then send best-effort [Signal API](/passkey-ui-flows/web/signal-api) reconciliation so the credential manager can hide or remove its stale client-side copy.
        - User has the possibility to create a new one.
    </Step>
</Steps>

<Warning>
    **Server revocation completes the security action, but not the credential-manager cleanup.** The stale passkey may keep appearing in [Conditional UI](/passkey-ui-flows/web/passkey-login/conditional-ui) and the account chooser until the credential manager acts on a signal. The user can select the stale passkey and complete device authorization, but the server rejects the assertion and login fails. This can make the settings screen appear broken. Call `signalAllAcceptedCredentials` from the revoke action, but treat signalling as best-effort because providers may hide, remove or ignore the credential. See the [WebAuthn Signal API](/passkey-ui-flows/web/signal-api).
</Warning>

### Passkey List Error States

<ToolingFrame
    imageURL="/images/authentication-flow/web-app/desktop/passkey-list-errors-macos.webp"
    caption="Representative web passkey list error states shown on macOS"
    imageName="passkey-list-errors-macos.webp"
/>

<Steps>
    <Step title="Passkey List Loading Error">
        - The list of passkeys fails to load (e.g., due to network or system
        error).
    </Step>
    <Step title="User Aborts Passkey Creation">
        - User cancels creation during system prompts or internal dialogs. No
        new passkey is added in the list.
    </Step>
    <Step title="Passkey Creation Failed Due to API Errors">
        - User experiences errors from backend/API during passkey creation. The
        error is communicated clearly.
    </Step>
    <Step title="Passkey Deletion Fails">
        - Deletion of the passkey returns an error due to system or API failure.
    </Step>
    <Step title="Passkey Already Exists">
        - Attempting to register a passkey that is already present prompts an
        informative error.
    </Step>
    <Step title="No Passkey Support">
        - When the client cannot create a passkey, omit or disable only the add action with an accurate explanation. Keep the server-side list and revoke actions available.
    </Step>
</Steps>
