## Acceptance criteria



| Benchmark as | Expected adoption impact |
| --- | --- |
| Conditional | Mid |

<Note>
    A web authentication exception is not proof that a passkey was deleted or
    is permanently broken. This flow creates an additional usable credential;
    the relying party does not silently revoke older server records or infer
    provider-side replacement from a successful client ceremony.
</Note>

| ID | Level | Acceptance criterion | How to verify |
| --- | --- | --- | --- |
| **W2.5-AC01** | Core | A cancelled or failed passkey attempt can indicate that the expected passkey is not available on the current client, for example after a device or credential-provider change. Offer creation only after the user successfully signs in with fallback and the current client is ready to create a passkey. | Cancel or fail a passkey attempt on a client without the expected passkey, then complete fallback and confirm that creation is offered. Repeat with unsuccessful fallback and with a client that cannot create a passkey; the offer does not appear. |
| **W2.5-AC02** | Core | The prompt describes the outcome as adding a passkey for future sign-in on the current environment, not repairing or replacing an existing credential. | Review the rendered recovery prompt. It describes an additional credential and makes no repair or replacement claim. |
| **W2.5-AC03** | Core | Successful creation does not silently revoke an older server credential; any server-side invalidation remains a separately authorized, risk-based action. | Create an additional passkey while an older credential remains usable elsewhere. Confirm both server records remain bound until a separate invalidation action succeeds. |
| **W2.5-AC04** | Core | After verified creation, recovery eligibility is recomputed from current state without marking an older credential repaired, replaced, or revoked. | Complete creation and repeat the recovery decision. Confirm routing uses current state and makes no unsupported claim about an older credential. |
| **W2.5-AC05** | Core | The additional passkey is stored for the authenticated account and can complete a later passkey sign-in to that same account. | Complete the recovery creation flow, sign out and use the additional passkey to sign in again. The assertion resolves to the same account. |
